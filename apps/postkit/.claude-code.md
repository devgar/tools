# postkit — multi-platform social media scheduler

## Arquitectura

Tres iteraciones:
1. **Iter 1 (verify)**: Carga config, valida credenciales
2. **Iter 2 (compose)**: SourcePost → PreparedPost (plan declarativo sin I/O)
3. **Iter 3 (execute)**: Ejecuta plan contra API de plataforma

## Spike actual

- Provider trait con `verify()`, `compose()`, `execute()`
- Bluesky fully implemented (auth, text composition, facets, media upload)
- CLI en clap con comandos: accounts, verify, compose, publish
- Config en TOML, posts en TOML

## Próximos pasos típicos

1. Generalizar: extraer Bluesky a crate separado, añadir X provider
2. Persistencia: SQLite + schema, tabla scheduled_posts
3. Daemon: worker tokio con scheduler, systemd service
4. Widget Eww: endpoint JSON del daemon mostrando próximos 3 posts

## Notas de diseño

- `compose()` es pura (sin I/O) → fácil de testear y previsualizar
- Byte offsets para facets (AT Protocol requirement)
- Grafeme counting para límites de texto
- App passwords de Bluesky en credenciales.toml separado (gitignored)
